## 1. 题目：TD-9 显式闭环——`/reject` reason 落进 lessons 候选

### 当前 TD-9 真实状态（基于 [`sprint4-milestone.md`](../sprint4-milestone.md) §3）

> "TD-9 闭环但未正式关闭：reject reason 通过 transcript 进入 Scribe prompt，但**没有'显式 reject→lesson 候选'的捷径**。"

也就是说 reject reason 当前以**隐式**形式喂给 Scribe（混在 thread transcript 里），Scribe 可能输出 lesson、也可能没输出。**问题**：

1. 不显式 → 用户给的 reject reason 经常被 Scribe 漏掉
2. 不可控 → 不知道哪条 reject 产生了哪条 lesson
3. 反馈无奖励 → 用户给了 reject reason 没看到任何"它被沉淀了"的反馈

### 目标：TD-9 显式化

- **用户 reject 一个 step 时**，reject reason 立即作为一条 `lessons` 候选记录（`review_status='pending'`）
- Intelligence Tab Pending Queue 里显示该候选，**标注来源 "From /reject in <thread>"**
- 用户在 Pending Queue 看到 → Approve 后进入 `.slark/knowledge/lessons.jsonl`（D-25 决议路径）

### 为什么挑这个题目做 dogfood

| 维度 | 说明 |
|------|------|
| 闭环覆盖度 | 走过 L1（打开项目）→ L2（创建团队，至少 Architect + Dev + Reviewer）→ L3（用 feature-development 模板）→ L4（trigger workflow，跑到 Reviewer 那一步）→ L5（用户 reject + 写 reason）→ L6（Scribe / 显式 lesson 候选 → Approve）→ L7（在 Intelligence Tab 看沉淀） |
| 大小 | 1~2 小时内可跑完一圈，不会失焦 |
| 价值 | TD-9 是 [`focus-core-loop.md`](../focus-core-loop.md) §6 Sprint 9 G2 范围内"反馈姿势可见性"最小切入点；跑通即可作为 Sprint 8/9 起点 |
| 风险 | 涉及 Scribe + Workflow + Intelligence 三处，dogfood 暴露面足够广 |

### 🚨 关键 bug：Lo-26（架构级阻塞）

**症状**：L5 reject 后 v2 设计 → `/approve` → workflow 进入 step 2 implement → **立即失败**：

```
[12] ✓ Approval received — proceeding to step "implement"
[13] ⚠ Workflow failed — step "implement": agent "@Dev" is not a member of this channel
```

**根因**：

| 数据 | 值 |
|---|---|
| Builtin workflow `feature-development.yaml` 期望的 implementer | `@Dev`（硬编码）|
| Team Architect 实际推荐的 implementer | `@BackendDev`（自由命名）|
| 错位结果 | router 找不到 `@Dev` → workflow fail |

**影响**：

- **任何 Goal 触发的 builtin workflow** 几乎都会触发这个 bug——除非 Team Architect 巧合推荐恰好叫 `Dev/Reviewer/QA` 的 agent
- L4 真实任务跑完的成功率几乎为 0
- L6 Scribe 永远等不到（workflow fail 不触发 Scribe）

**修复方向**（候选）：

1. **方案 A（推荐）**：workflow YAML 用**角色占位符** like `@implementer` `@reviewer` `@qa`，runtime 由 messageRouter 按 team 角色映射到具体 agent name（参考 Cursor commands `%S` `%C` placeholders 的思路）
2. **方案 B**：Team Architect prompt 加约束："推荐时**必须使用** `Architect / Dev / Reviewer / QA` 等标准 name，便于 builtin workflow 复用"
3. **方案 C**：Build Team modal 检测 workflow 期望 name 与推荐 name 的 diff，让用户选择"标准化命名"还是"自由命名+自动改 workflow"

→ 在 §4.3 Sprint 8 backlog 单独立项 **S-2**（紧急），优先级高于 S-1 战略 pivot。

## 6. 战略反思（Lo-25 引发，第一轮 dogfood 最大收获）

### 6.1 现象

第一轮 dogfood 用 TD-9 测 reject reason 沉淀路径。在 L5 步用 `/reject 示例数据请用更真实的业务场景...` 触发 Architect 重新设计时，**Architect 在第二次输出里主动声明并实际创建了** `/Users/kaikxiao/code/dogfood-sandbox/.cursor/rules/sample-data-taste.mdc`（`alwaysApply: true`，1240 字节，反例 5 条 + 正例 6 条 + 适用范围 4 类 + 给 AI agent 的明确指引）。

**关键事实**：这件事不是 Slark 设计或要求的，是 **cursor-agent / claude-opus-4-7 自带的能力**。

### 6.2 设计意图 vs 实际行为

| 维度 | Slark 设计意图（product-brief D-1/D-2 + TD-9 闭环）| Architect 实际行为 |
|---|---|---|
| 沉淀路径 | reject reason → Scribe → `.slark/knowledge/lessons.jsonl` | Architect 第一人称 → `<workspace>/.cursor/rules/*.mdc` |
| 数据格式 | JSONL 每行一条（lesson_id / scope / kind / content / source） | Markdown + frontmatter（description / alwaysApply）+ 反例/正例/适用范围 |
| 生效机制 | ContextBuilder 加载 lessons.jsonl 拼到 system prompt 顶部 | Cursor 原生 `alwaysApply: true`（cursor-agent 默认行为） |
| 跨 agent | Slark 团队内所有 agent 都能用 | **任何用 `<workspace>` 的 cursor-agent / cursor-sdk / cursor IDE 都自动用** |
| Git 管理 | `.slark/` 目录已可 git-host（D-2） | `.cursor/rules/` 已经是社区/Cursor 标准 git artifact |
| 可编辑 | 必须经 Slark UI Pending Queue | 用户可在 IDE 直接 vim 编辑 |

### 6.3 战略选择（已选 pivot-manage）

**选项 A（已选 ✅）：Slark 不重新发明知识层，pivot 到组织和管理 `.cursor/rules/*.mdc`**
- ✅ 拥抱模型已有能力 / 社区标准
- ✅ 用户可在 Slark 或 IDE 两边编辑
- ✅ git-committable，per-project storage 精神保留
- ⚠️ 跨 runtime 兼容需要适配层（codex / 通用 SDK 用 system prompt 注入）

选项 B（未选）：职责划分 —— lessons.jsonl 是 runtime-agnostic 反思；`.cursor/rules/` 是 cursor 战术
- 优点：架构清晰
- 缺点：用户视角"两个仓库要看"会困惑

选项 C（未选）：TD-9 重定义 —— `/reject reason` 成为 rule 候选而非 lesson 候选
- 是选项 A 的子集

### 6.4 战略转向对现有路线的影响

| 维度 | 转向前（focus-core-loop.md v0.1 预期）| 转向后 |
|---|---|---|
| Sprint 8 G1 反馈姿势 | reject reason 显式入 Pending Queue（lesson 候选）| reject reason 显式入 Pending Queue（**`.mdc` 草稿候选**） |
| Sprint 8 G2 即时回路 | Coach 看 reject pattern 提建议 | Coach 看 reject pattern 提 **rule 草稿** |
| Sprint 8 G4 团队级视图 | Intelligence Tab = lessons review | Intelligence Tab = **Rules Dashboard**（mdc CRUD + 启用/禁用） |
| `.slark/knowledge/lessons.jsonl` | 第一性知识层 | **降级为 fallback 或归档**，新流量都去 `.cursor/rules/` |
| 多 runtime 解锁条件 | 自由切换 | **必须先做 rules → runtime 适配层**（cursor 直接用，codex 转译） |

### 6.5 待决策（下次 dogfood 之前要明确）

1. **历史 lessons.jsonl 数据迁移**：现有 `.slark/knowledge/lessons.jsonl` 怎么处理？归档 / 迁移 mdc / 废弃？
